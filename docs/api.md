# Sculpt Backend API Reference

This reference is derived from the application route, validation, controller, and service code. The API base path is `/api/v1`; paths below are relative to the server origin.

## Conventions

- Send JSON request bodies with `Content-Type: application/json`.
- Protected endpoints require a valid Better Auth session. Browser clients must send the session cookie (for example, `fetch(..., { credentials: "include" })`).
- Application endpoints except the health check pass through the general rate limit: **100 requests per minute per IP address**. Workout generation also has a **10 requests per hour per authenticated user** limit. Upload-URL generation also has a **20 requests per minute per authenticated user** limit. Better Auth endpoints use a separate **20 requests per 15 minutes per IP address** limit.
- A request ID is accepted through `X-Request-ID` or generated by the server. It is returned in the `X-Request-ID` response header. The rate-limit and request-ID headers are exposed to allowed CORS origins.
- Successful application responses use `{ "status": "success", "data": ... }`, except `/health`, which has its own response shape. Some successful responses also include `message` or `results`.

## Health

### `GET /health`

Public server health check.

**200 response**

```json
{
  "status": "ok",
  "timestamp": "2026-01-01T00:00:00.000Z"
}
```

## Authentication

Better Auth owns and serves authentication endpoints beneath `/api/v1/auth/*`. This application mounts Better Auth at that path with email/password authentication, Google social sign-in, password-reset email delivery, account deletion, and the Better Auth admin plugin enabled.

Authentication endpoint request and response contracts are supplied by the installed Better Auth version, not by this application’s route controllers. Use the Better Auth client or its version-matched documentation for those contracts. Application-specific endpoints are listed below.

## Workout plans

All workout endpoints require authentication.

### `GET /api/v1/workout/plan`

Returns the authenticated user’s single active workout plan.

**200 response**

```json
{
  "status": "success",
  "data": {
    "_id": "plan-id",
    "userId": "user-id",
    "source": "ai",
    "planName": "Beginner Full Body",
    "programTheme": "Strength",
    "imageKey": "optional-s3-key",
    "prioritizedMuscles": ["Chest"],
    "neutralPoints": ["Quads"],
    "weakPoints": ["Calves"],
    "trainingDays": 4,
    "sessions": [
      {
        "sessionOrder": 1,
        "focusAreas": ["Chest", "Triceps"],
        "exercises": [
          {
            "name": "Bench Press",
            "sets": 3,
            "repRange": "8-10",
            "alternates": [
              { "name": "Dumbbell Bench Press", "sets": 3, "repRange": "8-10" }
            ]
          }
        ],
        "notes": "Optional session notes"
      }
    ],
    "createdAt": "2026-01-01T00:00:00.000Z",
    "updatedAt": "2026-01-01T00:00:00.000Z"
  }
}
```

`source` is either `"ai"` or `"predefined"`. Returns **404** when the user has no workout plan.

### `GET /api/v1/workout/plan/summary`

Returns a compact version of the current workout plan.

**200 response**

```json
{
  "status": "success",
  "data": {
    "planName": "Beginner Full Body",
    "programTheme": "Strength",
    "trainingDays": 4,
    "createdAt": "2026-01-01T00:00:00.000Z"
  }
}
```

Returns **404** when the user has no workout plan.

### `GET /api/v1/workout/plan/session/:sessionOrder`

Returns one session in the current plan. `sessionOrder` must be an integer greater than or equal to `1`.

**200 response**

```json
{
  "status": "success",
  "data": {
    "sessionOrder": 1,
    "focusAreas": ["Chest", "Triceps"],
    "exercises": [
      {
        "name": "Bench Press",
        "sets": 3,
        "repRange": "8-10",
        "alternates": []
      }
    ],
    "notes": "Optional session notes"
  }
}
```

Returns **404** if the plan or requested session does not exist.

### `GET /api/v1/workout/plan/session/:sessionOrder/exercises`

Returns only the planned exercise name, set count, and rep range for a session. `sessionOrder` must be an integer greater than or equal to `1`.

**200 response**

```json
{
  "status": "success",
  "data": [
    { "name": "Bench Press", "sets": 3, "repRange": "8-10" }
  ]
}
```

Alternate exercises and session notes are intentionally not included. Returns **404** if the plan or session does not exist.

### `GET /api/v1/workout/plan/muscles`

Returns the current plan’s muscle-group classifications.

**200 response**

```json
{
  "status": "success",
  "data": {
    "prioritizedMuscles": ["Chest"],
    "neutralPoints": ["Quads"],
    "weakPoints": ["Calves"]
  }
}
```

Returns **404** when the user has no workout plan.

### `POST /api/v1/workout/generate`

Generates and stores an AI workout plan. A user may have only one workout plan; attempting to generate another one returns **409**. Plans are cached by normalized fictional-character archetype and training-day count, so a later matching request reuses the generated plan without another AI inference. The generated plan is rejected with **502** if the AI returns a number of training days different from the request.

**Request body**

```json
{
  "archetype": "beginner strength athlete",
  "trainingDays": 4
}
```

| Field | Required | Constraints |
| --- | --- | --- |
| `archetype` | Yes | String after trimming; 1–50 characters |
| `trainingDays` | Yes | Integer from 3 through 6 |

**201 response**

```json
{
  "status": "success",
  "data": { "_id": "plan-id", "source": "ai", "trainingDays": 4 }
}
```

The returned `data` is the complete stored workout-plan document, in the same shape as `GET /api/v1/workout/plan`.

### `POST /api/v1/workout/predefined/:planKey/assign`

Copies a predefined plan to the authenticated user. A user who already has a workout plan receives **409**. Returns **404** when `planKey` does not exist.

`planKey` must be a non-empty path value. No request body is required.

**201 response**

```json
{
  "status": "success",
  "message": "Workout plan assigned successfully",
  "data": { "_id": "plan-id", "source": "predefined", "trainingDays": 4 }
}
```

`data` is the complete stored workout-plan document.

## One-rep maximum (1RM)

### `POST /api/v1/workout/calculate/1rm`

Authenticated endpoint for the `1rm.service` calculation. It uses the Epley formula, rounds the estimated 1RM to the nearest whole number, and derives rounded 50%, 60%, 70%, 80%, and 90% training weights from that rounded value.

**Request body**

```json
{
  "weight": 135,
  "reps": 5
}
```

| Field | Required | Constraints |
| --- | --- | --- |
| `weight` | Yes | Number from 20 through 500 |
| `reps` | Yes | Integer from 1 through 10 |

**200 response**

```json
{
  "status": "success",
  "data": {
    "oneRepMax": 158,
    "trainingWeights": {
      "fiftyPercent": 79,
      "sixtyPercent": 95,
      "seventyPercent": 111,
      "eightyPercent": 126,
      "ninetyPercent": 142
    }
  }
}
```

## Workout logs

All workout-log endpoints require authentication. Logs are always scoped to the authenticated user.

### `GET /api/v1/workout/logs`

Returns all of the user’s workout logs in ascending `date` order.

**200 response**

```json
{
  "status": "success",
  "data": [
    {
      "_id": "log-id",
      "userId": "user-id",
      "sessionOrder": 1,
      "date": "2026-01-01T00:00:00.000Z",
      "exercises": [
        {
          "name": "Bench Press",
          "performedSets": [
            { "weight": 135, "reps": 8 },
            { "weight": 140, "reps": 7 }
          ]
        }
      ],
      "createdAt": "2026-01-01T00:00:00.000Z",
      "updatedAt": "2026-01-01T00:00:00.000Z"
    }
  ]
}
```

### `POST /api/v1/workout/logs`

Creates a workout log. The server supplies `date`, `createdAt`, and `updatedAt`.

**Request body**

```json
{
  "sessionOrder": 1,
  "exercises": [
    {
      "name": "Bench Press",
      "performedSets": [
        { "weight": 135, "reps": 8 }
      ]
    }
  ]
}
```

`sessionOrder` is a required integer of at least `1`. At least one exercise is required. Each exercise requires a trimmed, non-empty `name` and at least one set. Each set requires a non-negative numeric `weight` and an integer `reps` of at least `1`.

**201 response**

```json
{
  "status": "success",
  "message": "Workout logged successfully",
  "data": { "_id": "log-id", "sessionOrder": 1, "exercises": [] }
}
```

### `PUT /api/v1/workout/logs/:logId`

Updates the authenticated user’s workout log. `logId` must be a non-empty path value. Both body fields are optional, so `{}` is accepted as a no-op update.

**Request body**

```json
{
  "sessionOrder": 2,
  "exercises": [
    {
      "name": "Deadlift",
      "performedSets": [{ "weight": 200, "reps": 3 }]
    }
  ]
}
```

When provided, `sessionOrder`, exercises, and performed sets follow the same validation rules as `POST /api/v1/workout/logs`.

**200 response**

```json
{
  "status": "success",
  "data": { "_id": "log-id", "sessionOrder": 2, "exercises": [] }
}
```

Returns **404** when the log does not exist or belongs to another user.

## Predefined workout plans

The predefined-plan catalogue is public; no authentication is required.

### `GET /api/v1/predefined-plans`

Returns all plans, newest first.

**200 response**

```json
{
  "status": "success",
  "results": 1,
  "data": [
    {
      "planKey": "kratos-program",
      "planName": "Kratos Program",
      "programTheme": "Kratos from God of War",
      "imageKey": "/uploads/workout.jpg",
      "prioritizedMuscles": ["Traps"],
      "neutralPoints": ["Chest"],
      "weakPoints": ["Calves"],
      "trainingDays": 5,
      "sessions": []
    }
  ]
}
```

### `GET /api/v1/predefined-plans/:planKey`

Returns a single predefined plan. `planKey` is trimmed and must not be empty.

**200 response**

```json
{
  "status": "success",
  "data": {
    "planKey": "kratos-program",
    "planName": "Kratos Program",
    "programTheme": "Kratos from God of War",
    "prioritizedMuscles": [],
    "neutralPoints": [],
    "weakPoints": [],
    "trainingDays": 5,
    "sessions": []
  }
}
```

Each session has `sessionOrder`, `focusAreas`, `exercises`, and optional `notes`. Each exercise has `name`, `sets`, `repRange`, and `alternates`. Returns **404** when no matching plan exists.

There are no application routes for creating, updating, deleting, or administrating predefined plans.

## Nutrition

All nutrition endpoints require authentication.

### `GET /api/v1/nutrition/get-profile`

Returns the authenticated user’s nutrition profile, or **404** if it has not been created.

**200 response**

```json
{
  "status": "success",
  "data": {
    "_id": "profile-id",
    "userId": "user-id",
    "goal": "maintain",
    "height": 180,
    "currentWeight": 75,
    "age": 30,
    "gender": "male",
    "activityLevel": "moderate",
    "bmr": 1730,
    "tdee": 2682,
    "calorieTarget": 2682,
    "macroTarget": {
      "macroSplit": "40-30-30",
      "carbs": 268,
      "fat": 89,
      "protein": 201
    },
    "createdAt": "2026-01-01T00:00:00.000Z",
    "updatedAt": "2026-01-01T00:00:00.000Z"
  }
}
```

### `POST /api/v1/nutrition/create-profile`

Creates one nutrition profile for the authenticated user. Returns **409** if one already exists.

### `PATCH /api/v1/nutrition/update-profile`

Recalculates and replaces the profile’s body metrics and targets. Returns **404** until a profile has been created.

Both endpoints require the same body:

```json
{
  "height": 180,
  "weight": 75,
  "age": 30,
  "gender": "male",
  "activityLevel": "moderate",
  "goal": "maintain",
  "macroSplit": "40-30-30"
}
```

| Field | Required | Constraints |
| --- | --- | --- |
| `height` | Yes | Number from 120 through 230 |
| `weight` | Yes | Number from 40 through 250 |
| `age` | Yes | Integer from 18 through 80 |
| `gender` | Yes | `male`, `female`, or `other` |
| `activityLevel` | Yes | `sedentary`, `light`, `moderate`, `active`, or `very_active` |
| `goal` | No | `maintain`, `lose`, or `gain`; defaults to `maintain` |
| `macroSplit` | No | `40-30-30`, `50-25-25`, or `60-20-20`; defaults to `40-30-30` |

The create response is **201** and the update response is **200**. Both return `{ "status": "success", "data": <nutrition-profile> }` in the shape shown for `GET /api/v1/nutrition/get-profile`.

### `POST /api/v1/nutrition/calculate-macros`

Calculates macro gram targets without creating or updating a profile.

**Request body**

```json
{
  "calories": 2400,
  "split": "40-30-30"
}
```

`calories` is a required integer from 1,000 through 10,000. `split` is optional and accepts the macro splits above; it defaults to `40-30-30`.

**200 response**

```json
{
  "status": "success",
  "data": {
    "carbs": 240,
    "fat": 80,
    "protein": 180
  }
}
```

## Exercise analysis

### `GET /api/v1/analysis/:exercise`

Requires authentication. `exercise` is trimmed and must contain 1–100 characters. The lookup is an exact exercise-name match against the user’s logged exercises. Returns **404** with `"No data"` when no matching log data exists.

**200 response**

```json
{
  "status": "success",
  "data": {
    "metrics": {
      "weight": { "current": 140, "change": 5, "weeklyChange": 2.5 },
      "volume": { "current": 3360, "change": 240, "weeklyChange": 120 }
    },
    "trends": {
      "weight": {
        "slope": 2.5,
        "rSquared": 0.8,
        "confidence": "high",
        "isVolatile": false,
        "direction": "up"
      },
      "volume": "insufficient data"
    },
    "history": [
      {
        "date": "2026-01-01T00:00:00.000Z",
        "weight": 140,
        "volume": 3360,
        "reps": 24
      }
    ]
  }
}
```

One matching workout log is enough to return exercise history. `metrics` is `null` until there are at least two matching exercise history points. Each trend is `"insufficient data"` until there are at least three matching points; otherwise it contains `slope`, `rSquared`, `confidence` (`low`, `medium`, or `high`), `isVolatile`, and `direction` (`stable`, `up`, or `down`). Logs that do not contain the requested exercise do not count.

## File upload URL

### `POST /api/v1/files/upload-url`

Requires authentication. Creates a presigned S3 `PutObject` URL. The URL expires after **300 seconds**. Upload the file to the returned URL using the declared `Content-Type`.

**Request body**

```json
{
  "category": "profile-picture",
  "fileName": "profile.jpg",
  "contentType": "image/jpeg"
}
```

| Field | Required | Constraints |
| --- | --- | --- |
| `category` | Yes | `profile-picture` or `workout-plan` |
| `fileName` | Yes | Trimmed string of 1–255 characters |
| `contentType` | Yes | `image/jpeg`, `image/png`, or `image/webp` |

**200 response**

```json
{
  "status": "success",
  "data": {
    "uploadUrl": "https://bucket.s3.amazonaws.com/signed-object-url",
    "key": "profile-pictures/user-id/uuid.jpg"
  }
}
```

## Errors

### Validation failure — 422

Route validation returns this response directly. `errors` contains Zod issue objects.

```json
{
  "message": "Validation failed",
  "errors": [
    {
      "code": "too_small",
      "path": ["body", "reps"],
      "message": "Reps must be at least 1"
    }
  ]
}
```

### Authentication failure — 401

```json
{
  "message": "Authentication required"
}
```

### Application and unexpected errors

Service errors and unhandled errors pass through the central error handler. Application errors include their specific status (commonly **404**, **409**, or **502**); unexpected errors use **500**.

```json
{
  "status": "error",
  "message": "Error description",
  "requestId": "request-id"
}
```

### Rate limiting — 429

```json
{
  "status": "error",
  "message": "Too many requests, please try again later",
  "retryAfter": 42
}
```

The response includes `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` headers.
